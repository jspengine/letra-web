# Constituição do Lançamento — Letra

**Versão:** 1.0.0  
**Data:** 2026-07-03  
**Status:** Ratificada

---

## Preâmbulo

Este documento define os princípios não-negociáveis que governam cada decisão, cada conteúdo e cada ação no projeto de lançamento do Letra. Toda escolha deve ser alinhada com estes princípios.

---

## Princípio 1: Verdade do Produto

O Letra é um **Mission Control para engenharia assistida por IA** — não é um chatbot, não é um assistant genérico, não é uma ferramenta de automação sem supervisão.

**Regras:**
- Nunca prometer capacidades que o produto não tem
- Nunca usar linguagem que implique autonomia total dos agentes
- Sempre enfatizar a supervisão humana como feature, não como limitação
- O posicionamento deve ser preciso: orquestração, não mágica

---

## Princípio 2: Voz da Marca

A voz do Letra é **técnica, clara, direta e confiável**. Sem hype exagerado, sem linguagem sci-fi, sem promessas vagas.

**Regras:**
- Usar linguagem operacional: "4 agentes ativos", não "IA pensando"
- Evitar: "revolucionário", "mágico", "autônomo total", "transformador"
- Priorizar: clareza, precisão, verificabilidade
- O tom é premium sem ser distante, técnico sem ser frio

---

## Princípio 3: Consistência Visual

Todo conteúdo visual deve seguir o brand-book.md rigorosamente. A identidade visual é modular, premium e escura.

**Regras:**
- Dark UI como base, Amber como acento operacional
- Nunca dominar a interface com Amber
- Fluxo visual `●──●──●──◆` como elemento central
- Sora para branding, Inter para UI, JetBrains Mono para código
- Contraste vem de hierarquia de superfícies, não de brilho

---

## Princípio 4: Precisão Técnica

Todo conteúdo técnico deve ser **correto, verificável e accionável**. Sem generalidades, sem pseudocódigo, sem exemplos que não compilam.

**Regras:**
- Todo comando deve ser testado antes de publicar
- Toda API reference deve ter exemplo funcional
- Toda feature description deve ser verificável no produto
- Links devem ser validados antes do launch

---

## Princípio 5: Audience-First

O conteúdo é escrito para o público-alvo, não para nós. Engenheiros que usam AI assistants e precisam de mais controle.

**Regras:**
- Começar pelo problema do usuário, não pela feature do produto
- Usar a linguagem do público: "workflow", "pipeline", "orchestration"
- Evitar jargão interno do produto que não é público
- Cada página deve responder: "por que isso importa para mim?"

---

## Princípio 6: Timing e Prioridade

O lançamento segue uma cadência definida. Não adiar entregas críticas por perfeccionismo.

**Regras:**
- **Semana 1-2**: Landing page + Brand site + Docs básicas
- **Semana 3-4**: Waitlist + Blog post + Community
- **Semana 5+**: Launch public + Marketing
- "Good enough" lançado no tempo certo > "Perfeito" lançado tarde

---

## Princípio 7: Métricas Acionáveis

Cada métrica coletada deve ter um propósito claro e uma ação associada.

**Regras:**
- Não coletar dados sem saber o que fazer com eles
- Cada métrica deve ter um target e um trigger de ação
- Priorizar métricas de engajamento sobre métricas de vaidade
- Dashboard deve ser revisado semanalmente durante o launch

---

## Anti-Drift Rules

Para evitar perda de foco:

1. **Todo conteúdo deve rastrear para uma spec** — nada de "ajudas rápidas" fora do fluxo
2. **Brand first** — antes de criar qualquer conteúdo, consultar brand-book.md
3. **Voice check** — todo texto público deve passar pelo filtro de voz da marca
4. **Technical review** — todo conteúdo técnico deve ser revisado por alguém que usa o produto
5. **Timing check** — se a entrega não está no cronograma, escalar ou cortar escopo

---

## Declaração de Missão do Lançamento

> Posicionar o Letra como a solução de referência para engenheiros que querem orquestrar agentes de IA com controle humano, clareza operacional e entrega verificável.
