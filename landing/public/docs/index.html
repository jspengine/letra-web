Installation

Install Letra globally via npm:

$ npm install -g letra

Verify installation:

$ letra --version
v0.5.3

That's it. No other dependencies required.

Quickstart

1

Create a workspace

A workspace holds all context, rules, and state for your project.

$ letra init my-project
✓ Workspace created
2

Add a spec

Define what needs to be built with acceptance criteria.

$ letra spec new login-flow
✓ Spec created at .letra/specs/login-flow/
3

Start a flow

Begin orchestrating agents through stages.

$ letra flow start login-flow
●──●──●──◆ Flow started

First Workspace

Letra organizes work through workspaces. Each workspace is a self-contained unit with its own flows, specs, agents, and evidence.

$ letra init my-project --template padrao
✓ Creating workspace...
✓ Default harness installed (v0.1.0)
✓ Ready at ./.letra/

Next: letra spec new to define your first item

Workspace

The workspace is the root aggregate. It represents a solution in progress. Everything — specs, flows, agents, gates — lives inside a workspace.

  • Created via letra init
  • Contains .letra/ directory with all state
  • Version-controlled with your project
  • One workspace = one solution

Flow

A flow moves work through stages: backlog → design → code → review → done. Each transition can require human approval via gates.

$ letra flow start <spec>
$ letra flow move <item> --to <stage>
$ letra flow board         # View all items

Gate

A gate is a checkpoint where human approval is required before work can proceed. No destructive action happens without explicit sign-off.

Gates appear in the UI as decision points. The CLI prompts for approval before continuing.

Spec

A spec is a specification document with acceptance criteria (ACs). Every feature must trace to a spec.

$ letra spec new <name>
✓ Creates .letra/specs/<name>/spec.md
$ letra validate         # Check AC status

Agent

Agents are LLMs configured with personas and constraints. In v1, Letra supports 3 personas: reviewer, security, and analyst.

Each agent has explicit rules: max files to review, required tests, forbidden actions. All agent output is presented for human approval.

Creating Flows

Flows define how work progresses through your development lifecycle. The default flow template is padrao with stages: backlog → design → code → review → done.

$ letra flow backlog add "Fix login bug" --spec auth
$ letra flow move ITEM-1 --to design --force
$ letra flow board
Backlog: 3 | Design: 1 | Code: 0 | Review: 0 | Done: 2

Working with Gates

Gates are the human-in-the-loop mechanism. Before critical actions (merge, deploy, stage transition), Letra requires human approval.

$ letra flow move ITEM-1 --to review
⏳ Awaiting human approval...
✓ Approved. Moving to review.

FAQ

What makes Letra different from other AI tools?

Letra is a coordination layer, not a code generator. It connects multiple agents, maintains context, requires human approval at critical points, and preserves evidence of every action.

Do I need to stop using my current AI tools?

No. Letra works alongside your existing tools. It orchestrates agents and manages flows, regardless of which LLMs or tools those agents use.

Is Letra open source?

Letra is built in the open. The workspace format and harness are fully transparent and inspectable.

How does pricing work?

Pricing is not yet announced. Join the waitlist for early access updates.

Can I use Letra with my team?

Yes. Workspaces can be shared via Git. Each team member can run Letra locally and interact with the same flows and gates.
